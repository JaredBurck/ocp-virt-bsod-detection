# coo — conventions

- **COO integration recipes here are [UNVALIDATED]** — unlike `acm/` (MCO) and `dashboards/` (Grafana Operator), the YAML in this directory has not been exercised against a live cluster. Product facts (versions, CRD schemas) are sourced from official Red Hat docs/errata; the specific wiring to this framework's existing alerts/dashboards/ACM artifacts is a documented starting point, not a proven path
- **COO's RHACM `UIPlugin` reads from MCO, it does not replace it** — `coo/uiplugin-monitoring.yaml`'s `acm.alertmanager`/`acm.thanosQuerier` URLs target the same `open-cluster-management-observability` Services that `acm/observability-deploy-guide.md` already stands up. Deploy it on the hub, after MCO, not instead of it
- **`MonitoringStack` (GA since COO 1.5.0) is deliberately not used for BSOD alerts** — the `alerts/` `PrometheusRule` CRs are designed against the platform Prometheus (CMO-managed, `openshift-monitoring`/`openshift-cnv`); moving them to a standalone `MonitoringStack` would require re-declaring `ServiceMonitor`/`PodMonitor` discovery for `virt-launcher`/`windows_exporter` and re-pointing every verification command across `alerts/README.md`, `windows-exporter/README.md`, and `docs/operator-runbook.md` — not attempted here
